**Replaces:** the React Three Fiber hero specified in

## 1. Why the three.js hero is being removed

The shipped hero renders four sources and a control plane from
`BoxGeometry`/`CylinderGeometry` primitives generated by
`scripts/hero-assets/build-fabric-assets.mjs` into five GLBs totalling 156 KB.
Measured on 2026-08-11:

- The largest client chunk on the site is **1.0 MB raw / 281 KB gzipped**, and
  it is three.js (`WebGLRenderer`, `BufferGeometry`, `PerspectiveCamera`).
- `three` + `@react-three/*` + `postprocessing` occupy **34 MB** of
  `node_modules`.
- The camera is a single hardcoded pose per breakpoint
  (`lib/hero-fabric.ts:320`, position `[6.83, 13.84, 10.12]`, fov 35), ~18 units
  from a 3-unit-wide scene. Nothing orbits. The free camera that justifies a
  real-time renderer is never used.

At that camera distance the primitives resolve to unrecognisable dark shapes.
Source labels are baked into the GLB as texture text and are illegible. Orange
is used for hardware *and* for the job route, so the route does not separate
from the scene. The six-step strip toggles two booleans
(`checkpointVisible`, `acceptedVisible`) and leaves four of six steps visually
identical.

None of this is fixable by tuning. The geometry carries no recognition, and the
engine cost buys a capability the design does not use.

## 2. What replaces it

**A live SVG isometric map of the coordinator doing its job.**

The coordinator — not the hardware — is the subject. It is the only component
of Zolli that no competitor has, and the landing page has never drawn it. Four
source classes sit on a diamond around it and exchange the three real protocol
events with it:

| Drawn as | Protocol event | What it tells the visitor |
|---|---|---|
| Orange token travelling outward | task lease | the coordinator hands work to a node it does not trust to survive |
| Soft ring pulsing at a node | heartbeat | when rings stop, the lease expires — this is how loss is detected |
| Pale token travelling inward | checkpoint | state moves off the machine so the machine becomes disposable |
| Route snaps red, ✗, node dims | lease expiry | a node died |
| New orange route to a different node | re-lease from checkpoint | the work continues |
| Green ✓, goodput recovers | accepted result | attempted ≠ accepted |

A readout strip under the map carries live values — active leases, checkpoint,
nodes lost, goodput, state — in the manner of Baseten's `512/1000 REPLICAS`
tags, which is what makes a diagram read as a running system rather than an
illustration.

Every source carries **platform badges** (Apple / Windows / Linux on Everyday,
Ubuntu / Docker on Owned, Google Cloud / AWS on Cloud, NVIDIA on Rented) so
compatibility is legible without prose.

Approved against a working prototype at
`apps/web/.artifacts/inspiration/coordinator.html`.

### 2.1 Design refinements over the prototype

The prototype proved the concept. These changes are what make it good:

1. **Isometric ground grid.** Faint dashed lines on the ground plane, fading
   at the edges. Gives the map structure and depth instead of objects floating
   in void.
2. **Elbow routing.** Routes travel along two isometric axes with a mitred
   corner instead of a straight diagonal. A starburst reads as decoration; an
   axis-aligned network reads as a map.
3. **Distinct node silhouettes.** Not four identical cubes:
   - *Everyday* — a cluster of several small low volumes (many small machines)
   - *Owned* — one tall volume with horizontal rack ruling
   - *Rented GPU* — two squat volumes with fan circles on the visible face
   - *Cloud / HPC* — a stepped group of uniform blocks
4. **The coordinator has an interior.** A checkpoint object is visibly held
   inside the plate stack, faintly lit. "State lives here" made literal.
5. **Depth cues.** Nodes further back render marginally dimmer and smaller.
6. **Type hierarchy.** Node names 12px cream; chips 10.5px mono in a bordered
   pill; the coordinator's own label larger, with a hairline rule above it.
7. **Particle trails.** Tokens carry a short fading tail so direction reads
   instantly rather than requiring the viewer to track a dot.
8. **Hover and focus.** Hovering or keyboard-focusing a source lifts it,
   brightens its route, and dims the other three.
9. **Orange means one thing.** The job's path. No orange hardware, no orange
   plinths, no orange grid. This single rule is most of the difference between
   the reference art and what shipped.

### 2.2 Scroll story

The map is `position: sticky` inside a tall scroll container. **Scroll progress
drives the story phase** — the Apple pattern, but with transforms rather than a
rendered frame sequence, because the beats are element state changes and CSS
does those natively at any resolution.

| Progress | Phase | Beat |
|---|---|---|
| 0.00–0.30 | `running` | leases out, heartbeats, checkpoints in |
| 0.30–0.50 | `lost` | a node goes dark, route snaps red, ✗, goodput dips |
| 0.50–0.75 | `resumed` | work re-leased to a different node from the checkpoint |
| 0.75–1.00 | `accepted` | green ✓, goodput recovers |

Falls back to a 16-second auto-running timer where scroll-linked animation is
unavailable, and to a single static representative frame under
`prefers-reduced-motion: reduce`.

## 3. Architecture

Pure logic separates from rendering so the geometry and the story are unit
testable without a DOM — matching how this repo already tests (474 tests, all
against `lib/`).

```
lib/coordinator-map.ts          PURE. projection, layout, routing, story, readouts
lib/coordinator-map-icons.ts    PURE. platform icon path data
lib/coordinator-map.test.ts     unit tests for the above

components/landing/coordinator-map/
  CoordinatorMap.tsx            composition + story state, owns the <svg>
  MapGrid.tsx                   ground grid
  MapCore.tsx                   the coordinator, its plates and held checkpoint
  MapNode.tsx                   one source: silhouette, badges, chip, label
  MapRoutes.tsx                 elbow routes and their per-phase state
  MapParticles.tsx              leases, checkpoints, heartbeat rings, trails
  MapReadout.tsx                the live value strip
  PlatformBadge.tsx             one circular badge
  useMapStory.ts                scroll/timer/reduced-motion → phase
```

`lib/hero-story.ts` **survives unchanged** — `HeroSourceKey`, `HERO_SOURCES`
and the runtime reducer are reused. Its 7 tests must stay green.

### 3.1 Module contract

`lib/coordinator-map.ts` exports exactly:

```ts
export type MapNodeKey = HeroSourceKey;              // "cloud"|"rented"|"owned"|"everyday"
export type MapPhase = "running" | "lost" | "resumed" | "accepted";
export type RouteState = "idle" | "active" | "failed" | "dimmed";

export interface Point { readonly x: number; readonly y: number }
export interface Viewport {
  readonly width: number; readonly height: number;
  readonly scale: number; readonly originX: number; readonly originY: number;
}

export const MAP_VIEWPORT_DESKTOP: Viewport;          // 1240 × 620
export const MAP_VIEWPORT_COMPACT: Viewport;          // stacked layout, ≤880px

export function project(x: number, y: number, z: number, vp: Viewport): Point;

export interface MapNodeSpec {
  readonly key: MapNodeKey;
  readonly name: string;
  readonly chip: string;
  readonly badges: readonly string[];
  readonly cell: { readonly x: number; readonly z: number };
  readonly size: { readonly w: number; readonly h: number; readonly d: number };
  readonly silhouette: "cluster" | "rack" | "cards" | "stepped";
}
export const MAP_NODES: readonly MapNodeSpec[];       // length 4
export const CORE_CELL: { readonly x: 0; readonly z: 0 };
export const VICTIM_KEY: MapNodeKey;                  // "everyday"
export const RESCUER_KEY: MapNodeKey;                 // "rented"

export function nodeAnchor(spec: MapNodeSpec, vp: Viewport): Point;
export function corePoint(vp: Viewport): Point;
export function elbowPath(from: Point, to: Point): string;   // SVG "M..L..L.."
export function gridLines(vp: Viewport): readonly string[];  // ground grid paths

export function phaseForProgress(progress: number): MapPhase;
export function routeStateFor(key: MapNodeKey, phase: MapPhase): RouteState;

export interface Readout {
  readonly leases: number; readonly checkpoint: string;
  readonly lost: number; readonly goodput: number; readonly state: string;
}
export function readoutFor(phase: MapPhase): Readout;
```

Invariants the tests must pin:

- `project` is a true isometric: `cos(30°)`/`sin(30°)`, +y is up on screen.
- `MAP_NODES` has 4 entries whose keys equal `HERO_SOURCES` keys exactly.
- Nodes occupy the four diamond corners; no two anchors within 40px.
- `elbowPath` returns three points and both segments are axis-aligned in
  isometric space.
- `phaseForProgress` is total over `[0,1]` and clamps outside it.
- `routeStateFor(VICTIM_KEY, "lost") === "failed"`.
- `routeStateFor(RESCUER_KEY, "resumed") === "active"`.
- `readoutFor("lost").lost === 1` and its goodput is below `readoutFor("running")`.
- No export reads `window`, `document`, or `Date.now()`.

## 6. Open decisions carried into implementation

**Platform marks.** Windows, Microsoft and AWS were removed from
`simple-icons` at those companies' request. Apple, Linux, NVIDIA, Google Cloud,
Docker and Ubuntu are present and used at their real paths. Windows ships as a
plain four-pane glyph drawn for this project; AWS ships as a type badge. The
visible weight mismatch between icon badges and type badges is accepted for
now. Dropping marks entirely in favour of text remains available and carries
zero trademark exposure.

**Story autoplay.** The scroll container drives the story. Where scroll linkage
is unavailable the timer runs the loop once and then idles until hover or
focus, rather than looping indefinitely — an indefinitely looping hero reads as
a banner advertisement.
